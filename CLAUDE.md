# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Android goal/habit tracker. Rust core (rules, stats, rewards, SQLite, backup) + Kotlin Jetpack Compose UI and Glance widget. Data stays on device. `PLAN.md` holds the exact domain rules (streaks, reward odds, pity, backup validation); `README.md` holds setup, install, and release steps. The user is new to Rust and Android, so keep explanations beginner-friendly.

## Commands

- Toolchain setup (once): `scripts/setup-toolchain.sh` (rustup into `~/.cargo`, Android targets, `cargo-ndk`, NDK; no sudo).
- Rust tests: `cd core && ~/.cargo/bin/cargo test`. Use `~/.cargo/bin/cargo`, not the system Rust (it has no Android targets). Single test: `~/.cargo/bin/cargo test <name>`.
- Lint/format: `cargo clippy`, `cargo fmt` (components pinned in `rust-toolchain.toml`).
- Debug install on phone: `cd android && ./gradlew installDebug`.
- Release APK: `cd android && ./gradlew assembleRelease` -> `android/app/build/outputs/apk/release/app-release.apk`. Signing key via `scripts/create-keystore.sh`; never commit or replace `android/release.keystore` / `keystore.properties`.
- Always smoke test release builds, not just debug: R8 minification broke Glance's old WorkManager, so `build.gradle.kts` pins a newer `work-runtime`.

## Architecture

- `core/src/lib.rs`: `GoalCore` is the only type Android calls (`#[uniffi::export]`). It wraps a `Mutex<Connection>`; one shared instance serves app and widget. Each multi-step change runs in a transaction. Modules: `goals`, `stats`, `rewards`, `backup`, `dates`, `db`, `model`. Integration-style tests in `core/src/tests.rs` use real SQLite files in temp dirs.
- Kotlin bindings are generated by UniFFI during the Gradle build (`preBuild` runs `buildRustLibs` via `cargo ndk` and `generateKotlinBindings`). Never edit generated code. A new `#[uniffi::export]` method shows up in Kotlin after the next build; Kotlin package is `dev.goaltracker.core`.
- Android UI in `android/app/src/main/java/dev/goaltracker/app/`. `AppController` bridges screens to the core: `read` for queries, `act`/`log` for changes; each change bumps `version` and screens reload on it. `TodayWidget.kt` (Glance) and `QuickLogActivity.kt` handle the widget path.

## Rules to preserve

- Rust never reads the clock for rule decisions. Kotlin passes today's date as `YYYY-MM-DD` (phone time zone) into every relevant call. Keep it that way so tests stay deterministic.
- Goal kind, period, and targets are immutable after creation (would rewrite history).
- Reward rolls are deterministic: `SHA-256(install_seed, goal_id, target_key)`; completions unique per `(goal, target_key)`. Undo must remove targets no longer satisfied and their rewards.
- Backups are untrusted input: restore validates application ID, schema version, `integrity_check`, and rejects triggers/views before atomic swap.
- Migrations: never edit a released `core/src/sql/NNN_*.sql`. Add a new numbered file and append it to `MIGRATIONS` in `core/src/db.rs` (`SCHEMA_VERSION` derives from its length).
- Schema is at version 25 (log times and shop, treat stock, XP and weekly boss, monsters, skips, weekdays, goal order, reminders, tasks, task-goal link, milestone tasks, task archive, icons and sample data, quit habits, goal trash, event end dates and skips, task templates, focus sessions, XP bonuses and daily quests, holidays, day notes, weekly review, routines). Goals deleted in the app go to a 30-day trash (`goals.deleted_date`); every query that lists goals must skip trashed ones. A quit habit (`goals.avoid`) logs slips, not successes. The theme (Dark fantasy, Parchment, or System) lives in `meta` so backups carry it; the old accent and OLED black values are ignored. Task archive, bulk edit, tags and search live in `tasks.rs` and `search.rs`. Every milestone has a mirror task (`tasks.milestone_id`, `ON DELETE CASCADE`): ticking either ticks both, renaming the task renames the milestone, and deleting the milestone deletes the task. The milestone stays the reward target, so ticking its task can win a treat. A milestone's task can't be trashed, moved to another goal, or repeat. Both are created in `goals.rs` through `tasks::create_milestone_task`. Tasks live in their own tables (`tasks`, `task_items`) and may be linked to a goal (`tasks.goal_id`, `ON DELETE SET NULL`), but they never log the goal, earn rewards, or count in stats; `core/src/tasks.rs` holds the rules and `core/src/quickadd.rs` parses lines like `Essay tomorrow !high #uni`. Deleted tasks sit in the trash for 30 days. Reminder alarms are Android-side (`Reminders.kt`); the core only stores times and builds the text. Weekday masks use Monday = 1 up to Sunday = 64; all seven days is stored as NULL.
- The day score (`core/src/score.rs`, rules in PLAN.md "V0.7.0 plan") only reads data: points for goals and tasks planned today, a percent, and a level (Spark, Blaze, Titan). It never changes goals, rewards, or stats. Keep it that way. XP and the weekly boss (`core/src/progress.rs`, migration 014) sit on top of it: `progress_tick(today)` snapshots today's points into `day_scores` (today's row is rewritten, older rows never are), so XP is the sum of `day_scores.earned`. A weekly boss (`weekly_bosses`, weeks start Monday) has 80% of the last four weeks' average points (at least 100); it falls when the week's points reach its health, and wins one treat in `boss_prizes`, listed through `list_draws`. Reminders are exact alarms when allowed, rebuilt on boot, update, and time changes; there is deliberately no foreground service.
- The calendar (`core/src/calendar.rs`, migration 015) only plans. `calendar_day(date)` merges events (`events`, repeat none/daily/weekly), tasks due that day (`tasks.due_time`, `tasks.duration`) and goals planned that day (`goals.block_start`, `goals.block_minutes`, planned through `today_items(date)`). Blocks without a start time show as "anytime" and default to 30 minutes. Events and blocks never change the day score, XP, streaks or rewards. A task's start time is cleared when its due day is cleared.
- Monsters (`core/src/monsters.rs`, rules in PLAN.md "Custom monsters"): health is worked out from history, only rounds and defeats are stored, and a recorded defeat or trophy is never undone. A slip heals a monster but never takes anything away. Prizes live in `monster_prizes` and appear in the treat list through `list_draws`. Monster names show as "a monster" outside the Monsters screens unless the person turns that off.
- XP bonuses (`xp_bonuses`, one row per date and kind, migration 019) are given and taken back by `progress_tick`: Titan day, daily quest and Blaze-streak bonuses for today vanish if the day is undone; boss and monster bonuses are permanent. `hero().xp` is `day_scores.earned` plus bonuses. The daily quest (`daily_quests`) is made once per day from the plan, picked by hash, and never changes; missing it costs nothing. Focus sessions (`focus.rs`), insights (`insights.rs`, read only), history, events and templates never change score, streaks or rewards.
- Quiet hours, the reminder sound switch and snooze are phone-side prefs in `Reminders.kt`, not in the core. Exports (`export.rs`) never include trashed items; task CSV import skips bad rows and caps at 1000. Sharing a backup goes through a cache-only `FileProvider`.
- Holiday mode (`holiday.rs`, migration 020): starting one adds `skips` rows for every live goal from its creation day and records only the rows it added in `holiday_skips`, so ending it removes only those and hand-made skips stay. Goals made later are not covered. Holiday days with nothing finished neither count in nor break the Blaze streak (`progress.rs` `day_records`). Tasks are not moved.
- Day notes (`notes.rs`, migration 021) are private: text up to 2,000 characters and a mood of 1 to 5. They never change score, XP, streaks or rewards, never show on widgets, notifications or the insights share text, and are in backups and the JSON export. Insights shows mood lines only with at least 7 moods.
- The weekly review (`review.rs`, migration 022) only plans: it saves a note and up to three focus items, gives no XP, and changes no score, streak or reward. Dismissing costs nothing. Routines (`routines.rs`, migration 023) are ordered lists of goals ticked through the normal log path, so finishing one gives nothing extra. Quit habits, archived and trashed goals cannot be steps.
- Bulk task edit (`TasksScreen.kt`, `bulk_update` in `tasks.rs`): selected tasks can be marked done, moved, given a priority, archived or trashed in one step. Milestone tasks are skipped for date changes.
- Treats (`rewards.rs`, migration 024): `treats.once` marks a one-time treat. Every draw (targets, weekly boss, monsters) picks from `rewards::jar_treats`, which leaves out removed treats and one-time treats already won, so undoing a win puts the treat back. The stock (`treat_stock`) is unused wins grouped by name; "Use one" marks the oldest as redeemed.
- 0.12.0 (migration 025): `entries.minute` is the minute of the day a log was made, passed by Kotlin (`toggle_check_in_at`, `log_amount_at`) and kept only for a log on the day itself; `time_profile` reads it. `goal_weekdays` and `year.rs` (`year_review`) only read data. The shop: coins are `hero().xp / 10` minus `shop_purchases.price`; `buy_treat` needs enough coins and puts the treat in the stock (purchases show in `list_draws` with `from_shop`, never in `unseen_draws`); `refund_purchase` undoes an unused one. One-time treats bought in the shop leave the jar like won ones.
- Every query that lists tasks uses `tasks::VISIBLE` so a trashed or archived goal's milestone tasks stay hidden (lists, archive, search, tags, calendar). `delete_milestone` always deletes the milestone's task, and `remove_orphan_milestone_tasks` runs on open and after a restore to clear leftovers whose milestone or goal is gone.
- Design (0.13.0, Kotlin only): `Theme.kt` holds the dark-fantasy and parchment palettes, the Cinzel display font (`res/font/cinzel.ttf`, OFL licence in `licenses/`) and the tablet-shaped `SoftCard`; `Game.kt` has the XP, boss and quest bars, the level badge and the coin chip; `Art.kt` draws the shield, boss, scroll, flame, coin and chest in code. Navigation has four bottom tabs: Today, Plan (Tasks and Calendar), Quests (Goals and Habits) and Hero (level, shop, stats, history, routines, holiday, rewards). Route names did not change. Looks are `ThemeMode` entries with a color scheme (`ThemeMode.scheme`) and a `Style` (`Looks.kt`: FANTASY for Dark fantasy and Parchment, PIXEL, NEON, CLEAN). The style sets card shape (`SoftCard`), M3 shapes, title font (Cinzel, Silkscreen, Orbitron, system; OFL licences in `licenses/`), how `Art.kt` pictures are drawn (`drawStyled`: painted, pixelated, neon outlines, flat), bars and badges in `Game.kt`, tab icons, the celebration, the tick pop and haptics (`Feel.style`). Clean and System follow the phone's dark setting. Widgets use only the dark-fantasy and parchment palettes through `WidgetTheme.kt`. Any new color pair must pass `ContrastTest`.
- The Guide (`Guide.kt`, Kotlin only): articles in `guideArticles`, opened from Settings and from the top-bar ? (`guideArticleFor(route)`). When a feature or rule changes, update its article.
- Versioning an update: bump `versionCode`/`versionName` in `android/app/build.gradle.kts`.
