# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Android goal/habit tracker. Rust core (rules, stats, rewards, SQLite, backup) + Kotlin Jetpack Compose UI and Glance widget. Data stays on device. `PLAN.md` holds the exact domain rules (streaks, reward odds, pity, backup validation); `README.md` holds setup, install, and release steps. The user is new to Rust and Android, so keep explanations beginner-friendly.

## Commands

- Toolchain setup (once): `scripts/setup-toolchain.sh` (rustup into `~/.cargo`, Android targets, `cargo-ndk`, NDK; no sudo).
- Rust tests: `cd core && ~/.cargo/bin/cargo test`. Use `~/.cargo/bin/cargo`, not the system Rust (it has no Android targets). Single test: `~/.cargo/bin/cargo test <name>`.
- Lint/format: `cargo clippy`, `cargo fmt` (components pinned in `rust-toolchain.toml`).
- Debug install on phone: `cd android && ./gradlew installDebug`.
- Release APK: `cd android && ./gradlew assembleRelease` -> `android/app/build/outputs/apk/release/app-release.apk`. Signing key via `scripts/create-keystore.sh`; never commit or replace `android/release.keystore` / `keystore.properties`.
- Always smoke test release builds, not just debug: R8 minification broke Glance's old WorkManager, so `build.gradle.kts` pins a newer `work-runtime`.

## Architecture

- `core/src/lib.rs`: `GoalCore` is the only type Android calls (`#[uniffi::export]`). It wraps a `Mutex<Connection>`; one shared instance serves app and widget. Each multi-step change runs in a transaction. Modules: `goals`, `stats`, `rewards`, `backup`, `dates`, `db`, `model`. Integration-style tests in `core/src/tests.rs` use real SQLite files in temp dirs.
- Kotlin bindings are generated by UniFFI during the Gradle build (`preBuild` runs `buildRustLibs` via `cargo ndk` and `generateKotlinBindings`). Never edit generated code. A new `#[uniffi::export]` method shows up in Kotlin after the next build; Kotlin package is `dev.goaltracker.core`.
- Android UI in `android/app/src/main/java/dev/goaltracker/app/`. `AppController` bridges screens to the core: `read` for queries, `act`/`log` for changes; each change bumps `version` and screens reload on it. `TodayWidget.kt` (Glance) and `QuickLogActivity.kt` handle the widget path.

## Rules to preserve

- Rust never reads the clock for rule decisions. Kotlin passes today's date as `YYYY-MM-DD` (phone time zone) into every relevant call. Keep it that way so tests stay deterministic.
- Goal kind, period, and targets are immutable after creation (would rewrite history).
- Reward rolls are deterministic: `SHA-256(install_seed, goal_id, target_key)`; completions unique per `(goal, target_key)`. Undo must remove targets no longer satisfied and their rewards.
- Backups are untrusted input: restore validates application ID, schema version, `integrity_check`, and rejects triggers/views before atomic swap.
- Migrations: never edit a released `core/src/sql/NNN_*.sql`. Add a new numbered file and append it to `MIGRATIONS` in `core/src/db.rs` (`SCHEMA_VERSION` derives from its length).
- Schema is at version 13 (monsters, skips, weekdays, goal order, reminders, tasks, task-goal link, milestone tasks, task archive, icons and sample data, quit habits, goal trash). Goals deleted in the app go to a 30-day trash (`goals.deleted_date`); every query that lists goals must skip trashed ones. A quit habit (`goals.avoid`) logs slips, not successes. Theme and accent live in `meta` so backups carry them. Task archive, bulk edit, tags and search live in `tasks.rs` and `search.rs`. Every milestone has a mirror task (`tasks.milestone_id`, `ON DELETE CASCADE`): ticking either ticks both, renaming the task renames the milestone, and deleting the milestone deletes the task. The milestone stays the reward target, so ticking its task can win a treat. A milestone's task can't be trashed, moved to another goal, or repeat. Both are created in `goals.rs` through `tasks::create_milestone_task`. Tasks live in their own tables (`tasks`, `task_items`) and may be linked to a goal (`tasks.goal_id`, `ON DELETE SET NULL`), but they never log the goal, earn rewards, or count in stats; `core/src/tasks.rs` holds the rules and `core/src/quickadd.rs` parses lines like `Essay tomorrow !high #uni`. Deleted tasks sit in the trash for 30 days. Reminder alarms are Android-side (`Reminders.kt`); the core only stores times and builds the text. Weekday masks use Monday = 1 up to Sunday = 64; all seven days is stored as NULL.
- The day score (`core/src/score.rs`, rules in PLAN.md "V0.7.0 plan") only reads data: points for goals and tasks planned today, a percent, and a level (Spark, Blaze, Titan). It never changes goals, rewards, or stats. Keep it that way.
- Monsters (`core/src/monsters.rs`, rules in PLAN.md "Custom monsters"): health is worked out from history, only rounds and defeats are stored, and a recorded defeat or trophy is never undone. A slip heals a monster but never takes anything away. Prizes live in `monster_prizes` and appear in the treat list through `list_draws`. Monster names show as "a monster" outside the Monsters screens unless the person turns that off.
- Versioning an update: bump `versionCode`/`versionName` in `android/app/build.gradle.kts`.
